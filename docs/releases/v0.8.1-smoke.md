# Vura 0.8.1 release smoke evidence

September 6, 2026. Agent-executed verification, not a claim of universal production
readiness or a person's visual approval. Publication and final registry results
are recorded on [release PR #139](https://github.com/CelsianJs/vura/pull/139).
The corrective changes are in [PR #141](https://github.com/CelsianJs/vura/pull/141).

## Real consumer paths

The candidate was built and packed, then installed into fresh temporary projects.
Vura packages came from candidate tarballs; What and Celsian came from their public
registry releases, without local upstream overrides. One consumer followed the
generated scaffold; another used the existing expanded self-host audit fixtures.

| Flow | Observed result |
|---|---|
| Scaffold into a path containing spaces | Twelve source/config files emitted; npm installation and production build succeed. |
| Client page and API | Browser renders dashboard, fetches hello API, and counter changes 0 → 1. |
| Static page | HTML contains real page content with no executable script tags. |
| Server action | Browser obtains CSRF token and executes the action; response contains the expected result. Missing-token request is rejected with 403. |
| Middleware | Missing fixture session redirects with 302; authorized fixture session receives protected page with 200. |
| Streaming | Shell arrives before delayed content across multiple socket chunks; measured fixture shell about 3ms, delayed data about 154ms. These are local diagnostics, not benchmark claims. |
| Streaming cache/HEAD | `Cache-Control: private, no-store`; HEAD has no response body. |
| Malformed request | Vura returns 404 for the tested invalid percent-encoded path; subsequent normal request succeeds. |
| Expanded self-host suite | Packed runtime tests cover static/client/hybrid/server pages, loaders, action boundaries, hooks, hot WebSockets, cache invalidation, task execution and cron definitions. |

The first generic guide assertion was run against the expanded fixture rather than
the guide fixture and correctly reported missing `/dashboard` and `/api/hello`.
Those paths are intentionally absent there; the fresh generated scaffold and
fixture-specific checks above are the evidence, not that mismatched invocation.

## Documentation and package surfaces

- Actual browser navigation and desktop/mobile screenshots were captured for the
  public documentation, corrected local build, GitHub organization, and packed app.
- All 34 distinct same-origin quickstart href forms returned HTTP 200 after their
  configured trailing-slash redirects. All 11 package-README documentation URLs
  returned 200; misleading labels and source claims were reviewed separately.
- Mobile docs now expose the complete desktop navigation through native HTML
  disclosure. Independent browser checks confirm Enter, Space, Tab, focus styling,
  destination navigation, and operation with script execution disabled.
- Wide tables retain native table/header/cell semantics inside keyboard-focusable
  scroll regions. At a 390px browser viewport, document width stays within its
  375px content viewport; arrow-key scrolling moves the table, not the page.
- Desktop sidebar and both color themes remain functional. Visual comparison
  scored 94/pass as agent evidence, not owner acceptance or a new design direction.
- npm's website showed a security challenge, so its rendered README visual review
  is **unverified**. No challenge was bypassed. Registry metadata, tarballs and
  install verification are separate accessible surfaces.

## Regressions fixed during the audit

- Explicit IPv4 fixture URLs avoid ambiguous `localhost` resolution. A prior
  local run received non-HTTP bytes; an IPv4/IPv6 endpoint collision is a plausible
  explanation, not proven history because that failed fixture port was not recorded.
- Scaffold next-step commands are tested by executing the printed POSIX `cd`,
  including spaces, apostrophes, and relative dash-prefixed paths. Windows shell
  guidance is not claimed as verified by these POSIX tests.
- Public task documentation and emitted TypeScript declarations no longer promise
  exactly-once external side effects. Checkpoint replay and provider idempotency
  are distinct, and standalone local step state is in-process.
- Managed deployment documentation matches the implemented credential/project/
  build flow and public private-beta access-code requirement. Installing the
  framework does not grant hosted-service access.
- Adapter restrictions are attributed to Vura's generated adapters, not universal
  provider limitations. Fresh Node deployments must install runtime dependencies.

## Verification and limitations

The corrected source slice passed a clean-tree `release:check` with 1,154 tests
before the final dash-prefix regression; that final targeted suite passes 7/7.
Both production and full dependency audits report no known vulnerabilities.
All eight package-size budgets pass without raising limits. Docs build 33 pages;
two built-HTML navigation/table checks run in both configured docs CI workflows.
Independent security, product, code-quality, PM and real-browser UX reviewers
checked the corrective slice; their actionable findings were repaired.

Final upstream pin changes, final-commit CI, fresh packed smoke, and the published
registry install must be verified after the independent upstream release. Their
exact commit/workflow evidence is attached to the release PR; earlier counts
above are labeled snapshots and must not silently substitute for that final pass.

Not proved by this OSS patch smoke: admitted managed signup through a real
provider deployment/rollback, production tenant database isolation, paid billing
flows, backup restores, sustained load, or privileged production superadmin actions.
Those remain separate integration/operational work. Unsupported adapter middleware
and server actions, standalone durable task persistence, and compiled fine-grained
JSX SSR are not claimed as newly implemented by 0.8.1.
